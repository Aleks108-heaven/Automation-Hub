## 4. Detailed findings

### F-01 Biased shuffle in mixed quiz and flashcards (Medium, High confidence)

- **Area / checklist item:** Functional; language pitfalls, JavaScript reliability (weak randomness).
- **Score:** impact 2 (skewed practice, no data loss) x likelihood 5 (every use) = 10.
- **Evidence:** `app.js` used `all.sort(()=>Math.random()-.5)` for the mixed quiz and `[...list.keys()].sort(()=>Math.random()-.5)` for the flashcard shuffle. A 100,000-run measurement on a 6-item array put the first item back in position 0 in **28.7 %** of runs, against 16.7 % for a uniform shuffle. The file already defined a Fisher-Yates `shuffle`.
- **Root cause (hypothesis):** immediate: a comparator that is not a consistent ordering; underlying: the proper helper was added later in the file and not reused.
- **Alternative explanations:** none for the skew itself, which is measured. The size of the effect on the real 10-of-179 draw and on the flashcard list was not measured; the bias differs with array length.
- **Impact / risk:** practice is less varied than it looks; no security impact.
- **Fix (applied):** both call sites now use `shuffle(...)`.
- **Fix risk / rollback:** none known; revert the two lines.
- **Verification:** re-run the measurement against `shuffle`; the smoke test covers that the mixed quiz and flashcards still render.
- **References:** none (ECMAScript does not guarantee a uniform result for comparator shuffles).

### F-02 4 px horizontal scroll at 320 px in `api-testing` (Low, High confidence)

- **Area / checklist item:** Accessibility, WCAG 2.2 SC 1.4.10 Reflow.
- **Score:** impact 2 x likelihood 2 (only at 320 px) = 4.
- **Evidence:** at a 320 px viewport the document was 324 px wide in all four languages. A text-node probe found the cause: the paragraph in `data3.js` line 126 containing the unbroken token `request.get/put/patch/delete/fetch` in a `code.i` chip, which had no wrap rule.
- **Fix (applied):** `overflow-wrap:anywhere` on `code.i` in `part1.html`.
- **Verification:** `npm run test:integrity` now checks all 200 pages at 320 px and passes. The older 375 px smoke checks could not see this.

### F-03 Sources and inventory out of date (Low, High confidence)

- **Evidence:** `research-and-sources.md` listed 26 modules, 164 quiz questions and 63 flashcards while the hub had 31, 179 and 78; the five September modules had no source lists.
- **Fix (applied):** source lists for those five modules and the three new ones were generated from the hub's data, the inventory was corrected (34, 197, 71, 86), and a verification note records what was and was not re-checked.

### F-04 No Content-Security-Policy (Low, Medium confidence)

- **Area / checklist item:** Security headers; language pitfalls, JavaScript XSS.
- **Score:** impact 3 x likelihood 1 = 3. No injection path was found: every dynamic value is escaped, stored data and imported files pass the same validation, and routes are matched against a fixed list. A policy would only be defence in depth.
- **Evidence:** `part1.html` has no CSP `<meta>`. The page needs inline scripts and styles, so a policy would have to allow `'unsafe-inline'` for both and could still block `connect-src`, frames, objects, base URI and form targets.
- **Suggested fix (NOT applied):** add a `<meta http-equiv="Content-Security-Policy">` such as `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src data:; base-uri 'none'; form-action 'none'; object-src 'none'`.
- **Fix risk / rollback:** the published Claude artifact wraps the page in its own document, so the policy could break features there; it was not tested. Remove the tag to roll back.
- **Verification:** `npm run test:e2e` fails on any console error, so a violation locally would show; then open the artifact and click through it.

### F-05 Google Fonts request on every load (Low, High confidence)

- **Score:** impact 1 x likelihood 5 = 5.
- **Evidence:** the page loads IBM Plex from `fonts.googleapis.com` and `fonts.gstatic.com`. The README says it falls back offline but does not say that each visit sends the reader's IP address to Google.
- **Suggested fix (NOT applied):** either add one sentence to the README, or self-host the woff2 files (this grows the single HTML file and needs the font licences kept with it).

### F-06 CI image is a floating tag (Low, High confidence)

- **Area / checklist item:** language pitfalls, Infrastructure and CI (unpinned base images); security checklist item 13.
- **Score:** impact 3 x likelihood 1 = 3.
- **Evidence:** `.gitlab-ci.yml` uses `image: node:22-bookworm`. Playwright is pinned exactly (`1.63.0`) and the job uses `npm ci`, so the remaining drift is the image itself.
- **Suggested fix (NOT applied):** pin by digest (`node:22-bookworm@sha256:...`); I could not obtain a trustworthy digest offline.

### F-07 `npx serve` without a version (Info)

- **Evidence:** the README's "serve it locally" option runs `npx serve`, which fetches the latest package at run time. The Python alternative listed beside it has no such issue.
- **Suggested fix (NOT applied):** prefer the Python command, or pin a version after checking the current release.

### F-08 Reference files untracked in the repository root (Info)

- **Evidence:** `git status` shows the five Markdown guides (plus the longer design brief) and two `.plugin` zip archives as untracked. They are review tooling, not hub content, and the `.plugin` files are binary.
- **Suggested fix (NOT applied):** keep them out of the commit, or move them to a separate folder and add it to `.gitignore`.

### F-09 External links not confirmed by script (Info, Medium confidence)

- **Evidence:** of 93 external links, 86 returned 2xx/3xx. `dl.acm.org`, `bcs.org`, `consilium.europa.eu`, `fortunebusinessinsights.com`, `gartner.com` and `iso.org` returned 403 to a scripted request (typical bot blocking), and `applitools.com/platform/eyes/` timed out. None is confirmed dead.
- **Suggested fix:** open these seven in a browser before the next content-check date.

### F-10 Duplicate flashcard term (Info, High confidence)

- **Evidence:** the glossary holds "Boundary value analysis" twice: index 20 (Strategy and quality, a one-line definition) and index 39 (Certification, the 2-value and 3-value methods). It was found when a shuffle test counted 85 distinct terms among 86 cards.
- **Alternative explanation:** it may be intended, since the Certification card adds exam-level detail. With the "All" filter a reader sees the term twice.
- **Suggested fix (NOT applied):** keep both if intended, or merge them. Merging means removing an entry from the English glossary and from each translation at the same index, so do it in one change and re-run `npm run check:i18n`.

## 5. What looked healthy

- **Console, ids, headings, names, links:** 200 pages (50 routes x 4 languages), zero problems (`npm run test:integrity`).
- **Colour contrast:** 80 of 80 documented pairs meet WCAG AA in light and dark (`npm run check:contrast`), including control borders and the focus ring at 3:1.
- **Motion:** the hub has no CSS animations or smooth scrolling; `prefers-reduced-motion` removes transitions.
- **XSS and untrusted data:** dynamic text goes through `esc()`; saved progress and the running exam are validated on load; the new import uses the same `clean()` and a 1 MB cap, and is tested against a tampered file.
- **Dependencies:** `npm audit` reports 0 vulnerabilities; the lockfile exists; Playwright is pinned exactly.
- **Secrets:** no matches for common key, token, password or private-key patterns anywhere in the repository folder outside `node_modules` and `.git` (regular-expression scan; see limits).
- **Translations:** 218 of 218 sections, 197 of 197 quiz questions, 71 of 71 exam questions and 86 of 86 glossary entries in uk, pl and es.
- **Performance (measured, Chromium, `file://`):** DOMContentLoaded 388 ms, load 463 ms, JS heap about 10 MB, sidebar search about 8.6 ms per keystroke. The built file is 1.38 MB; roughly 0.8 MB of it is translations that every visitor downloads, which is the cost of the single-file design.
- **Line endings:** committed blobs are LF; Windows working copies are mixed, which git normalises on commit, so the CI `hub-build` comparison is unaffected.
